# Supervisor：终点驱动的监督设计

状态：已获用户确认。本文是产品设计，不是实现计划。

## 意图与范围

让用户一眼看懂“现在是否在监督、什么算完成”，减少重复推断和长篇输出。本轮只调整监督状态、任务契约与判定流程；不新增看板、预算系统或更多 Agent，也不改变主 Agent 的执行权限。

## 方案取舍

- **轻量调整**：保留复杂契约与现有判定流程，只统一操作、缩短展示；改动少，但不能解决反复推导和任务边界模糊。
- **终点驱动（已选择）**：先确认目标和完成条件，平时简短核对进展，目标变化或证据矛盾时再推断。调整更深入，但更便于判断终点是否正确。

## 已确认的要求

- 契约和判定应简洁明了，细节简要列出，有矛盾再深入推断。
- 暂停保留契约与监督进度，继续时沿用。
- 取消需额外确认一次；确认后移除当前有效契约、放弃本次监督进度。
- 取消只作用于 Supervisor，不中断主 Agent，不回滚代码或提交，也不删除对话历史。

## 具体设计提案

以下细节为本次设计提出的默认方案，随本文一起确认。

### 1. 一套操作，一个明确状态

| 操作 | 含义 |
| --- | --- |
| 开始 `start` | 建立并确认新契约后进入监督；已在监督时只报告状态，不重复建立任务。 |
| 暂停 `pause` | 停止后续监督和自动续跑，保留当前契约与进度，不中断主 Agent。 |
| 继续 `resume` | 仅恢复已暂停的任务；没有可恢复任务时提示使用 `start`。 |
| 取消 `cancel` | 二次确认后结束本次监督，契约与进度失效；之后只能通过 `start` 建立新任务。 |

- 主状态为：未开始、待确认、监督中、已暂停、已取消、已完成。判定中、等待额度等只是当前活动说明，不能遮蔽主状态。
- `on/off/reset` 不再作为正式操作；旧命令明确提示迁移，不静默映射为另一种操作，也不能绕过取消确认。
- 显式暂停、取消和完成状态高于项目默认值及 `--supervise`；普通输入、重载会话和下一次停止都不能偷偷恢复监督。自动启用仅适用于没有显式任务状态的新会话。
- 取消确认默认选择“不取消”；放弃确认则完全不改变状态。尚无任务时取消只报告当前状态。
- 契约确认前不得进入监督。关闭初始确认保留“未开始”；放弃替换契约则保留旧契约及其状态。推断失败不得自动建立通用执行契约。

### 2. 终点优先的短契约

确认时默认只展示：

- **目标**：一句话描述要交付的结果。
- **完成条件**：少量、可核验的条目，是“做到什么算完成”，而不是操作步骤。
- **必要限制**：范围、禁止事项和必须由人决定的边界。

过程安排、已确认的执行约束和技术细节作为附加信息简要列出，需要时再展开；不因缩短展示而丢弃约束。影响终点或授权的歧义必须先澄清。

### 3. 平时核对，异常时推断

- 每轮只核对完成条件，简短输出：结论、关键证据、未满足项和下一步；没有新增信息时不重复长篇契约。
- 进度可以更新，但不能借进度更新悄悄修改目标、完成条件或限制。
- 证据不足时补证，不直接宣告完成，也不因此重建整个契约。
- 证据冲突时针对冲突进一步推断；若影响任务终点或范围，提出契约修改，经用户确认后替换。
- 用户改变目标时同样重新确认。所有完成条件有足够证据后进入“已完成”，不继续围绕旧任务自动续跑。

### 4. 取消必须真正生效

确认取消后立即持久化终止状态，并让旧契约、旧进度、在途判官结果、额度等待、延迟回调及尚未发出的续跑消息失效。会话恢复时也不得把历史契约重新当作有效契约。

已经送交主 Agent 的消息不撤回，不调用中断主 Agent 的接口；取消后不再发送新的监督指令。暂停同样禁止在途结果触发续跑，但保留任务数据。

## 验收要点

1. 用户随时能直接读到监督状态；暂停、取消、完成后，默认配置和启动参数都不能自行重新启用它。
2. 放弃取消确认无副作用；确认取消后无有效契约和可恢复进度，而主 Agent 仍可运行。
3. 在判定、额度等待或延迟续跑期间取消，迟到结果均不能发送新指令；恢复会话也不会复活任务。
4. 放弃契约确认或推断失败不会意外启用监督；替换失败不破坏旧契约。
5. 正常轮次只简短核对终点，不反复改写契约；证据不足不算完成，目标或边界变更必须重新确认。

## 留给实现阶段

沿用现有 TypeScript 扩展与会话存储，不新增依赖。内部数据结构、旧会话迁移、异步失效机制及测试拆分由实现计划确定，但不得改变上述用户语义。
